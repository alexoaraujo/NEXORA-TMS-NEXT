# P0.1.1 — Application Role + RLS Hardening

## Execution contract
The test suite MUST execute using `nexora_app`, not a migration/owner role. This is required because PostgreSQL administrative privileges can bypass row security.

## Security requirements
- `nexora_app` is `NOSUPERUSER`, `NOBYPASSRLS`, `NOCREATEDB`, `NOCREATEROLE`, `NOINHERIT`.
- Runtime receives only schema USAGE and explicit DML/SELECT privileges.
- Tenant-owned tables use `FORCE ROW LEVEL SECURITY`.
- Tenant context is established from authenticated/authorized identity, never trusted from a client-supplied tenant id.
- Missing tenant context rejects tenant-owned writes.

## Acceptance suite
`database/tests/p0_1_1_rls_hardening.sql`

Required PASS:
1. A sees A.
2. A cannot see B.
3. B sees B.
4. B cannot see A.
5. A cannot update B.
6. A cannot insert as B.
7. Missing context cannot write.
8. Runtime role has no administrative/RLS-bypass flags.
9. Tenant-scoped tables have RLS enabled.
